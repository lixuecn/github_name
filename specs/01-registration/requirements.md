# 01 注册 — 需求

来源：[docs/需求.md](../../docs/需求.md)「功能需求 / 1. 注册」「技术说明」「非功能需求」

## 目标

新用户可以仅用「用户名 + 密码」在 Web 端与移动端注册账号，注册成功后自动登录。本目录同时负责全项目共享的「用户名认证」能力（服务端 `username` 插件、数据库字段、频率限制、客户端插件），[02-login](../02-login/requirements.md)、[03-logout-and-status](../03-logout-and-status/requirements.md)、[04-access-control](../04-access-control/requirements.md) 引用本目录的实现。

## 用户

尚未拥有账号的访客（Web 浏览器用户、iOS / Android App 用户）。

## 范围

- 用户名 + 密码 + 确认密码的注册表单（Web、Native）
- 服务端启用用户名认证、生成内部占位邮箱、开启注册频率限制
- 注册成功后自动登录与跳转

## 非目标

- 邮箱注册、邮箱验证、第三方登录、手机号注册、找回密码、双因素认证
- 修改用户名、头像等资料编辑

## 需求

### REQ-001 用户名认证基础能力

- REQ-001.01 服务端启用 Better Auth `username` 插件，`user` 表新增 `username`（唯一）与 `displayUsername` 字段。
  - 业务规则：用户名按小写归一化存储，`TestUser` 与 `testuser` 视为同一用户名。
  - 验收：数据库存在 `user.username` 唯一约束；以 `TestUser` 注册后 `username` 列为 `testuser`。
- REQ-001.02 注册时由系统生成内部占位邮箱，用户不可见、不可指定。
  - 触发：调用注册接口。
  - 预期：`user.email` 写入由用户名派生的占位邮箱；客户端传入的任何 email 均被忽略。
  - 异常边界：请求中缺少 `username` 时拒绝注册（不允许绕过用户名直接以邮箱注册）。
  - 验收：通过接口传入 `email=a@b.com` 注册，数据库中 email 不是 `a@b.com`；不带 username 的注册请求返回 4xx。
- REQ-001.03 注册接口开启频率限制。
  - 预期：同一来源短时间内超出阈值的注册请求返回 HTTP 429。
  - 验收：连续快速发起超过阈值的注册请求，后续请求返回 429。

### REQ-002 注册表单校验

- REQ-002.01 用户名：必填，3–20 个字符，仅允许字母、数字、下划线。
- REQ-002.02 密码：必填，至少 8 个字符。
- REQ-002.03 确认密码：必填，需与密码一致。
  - 触发：点击「注册」或在最后一个输入框按回车提交。
  - 预期：校验不通过时在对应字段下方显示中文错误，不发起网络请求。
  - 服务端同样校验用户名格式与长度，前端被绕过时返回 4xx。
  - 验收：分别输入 `ab`、`a-b-c`、21 个字符的用户名，7 位密码，两次不一致的密码，均显示对应错误且无注册请求发出；直接调用接口提交 `a-b` 用户名返回 4xx。

### REQ-003 注册提交与结果

- REQ-003.01 用户名已被占用（不区分大小写）时，提示「该用户名已被注册」。
- REQ-003.02 注册成功后自动登录：Web 跳转到 `/dashboard`，移动端停留在首页并显示已登录状态，均提示「注册成功」。
- REQ-003.03 提交过程中按钮显示加载状态并禁用，防止重复提交。
- REQ-003.04 触发频率限制时提示「请求过于频繁，请稍后再试」；其他未知错误提示「注册失败，请稍后再试」。
  - 验收：新用户名注册成功后 `user` 表新增 1 条记录且页面进入登录状态；用大小写不同的同一用户名再次注册，提示「该用户名已被注册」。

### REQ-004 界面与体验

- REQ-004.01 注册界面所有文案为中文，不出现任何邮箱字段或文案。
- REQ-004.02 每个输入框有可访问的 label；Web 表单支持回车提交。
- REQ-004.03 注册与登录界面可以互相切换（切换入口的另一端见 [02-login](../02-login/requirements.md)）。

## 待确认项

- Q-001（假设）占位邮箱格式为 `<归一化用户名>@users.invalid`（`.invalid` 为 RFC 2606 保留域名，不会被真实投递）。
- Q-002（假设）频率限制阈值：注册、登录接口每 IP 每 60 秒最多 5 次；其余接口沿用 Better Auth 默认值。
- Q-003（假设）`user.name` 填入用户名原样（未归一化），用于页面展示。
