# 03 Android App GitHub 人员展示 — 需求

来源：[docs/需求.md](../../docs/需求.md) §3、§4.3、§5、§6「Android App」。依赖 [01 GitHub 人员后端能力](../01-github-api/requirements.md) 的 `github.list` 接口与共享常量。

## 目标

Android App 作为只读展示端，打开即可浏览系统中已加入的 GitHub 人员，卡片直接展示主要信息，点击卡片在浏览器中打开 GitHub 主页。

## 用户

- 查看人员信息的移动端用户（无需登录）

## 范围

- 导航结构：底部 Tabs「人员」「设置」，移除脚手架的 Drawer、示例 Tabs、Modal
- 人员列表：搜索、排序、下拉刷新、上拉加载、卡片、状态界面
- 设置页：主题切换、后端连接状态、版本号
- 视觉规范：HeroUI Native + Uniwind、浅色 / 深色

## 非目标

- 新增 / 编辑 / 删除人员；人员详情页；登录
- iOS 专门适配与验收（代码共用）

## 需求

### REQ-001 导航结构

- REQ-001.01 App 启动后直接进入底部 Tabs，默认选中「人员」；另一个 Tab 为「设置」。脚手架的 Drawer、示例 Tab（Tab One / Explore）与 Modal 页面全部移除。
  - 验收：启动后看到「人员」列表与底部两个 Tab；不存在抽屉菜单与 Modal 路由。

### REQ-002 人员列表

- REQ-002.01 页头显示大标题「GitHub 人员」与总数「N 人」（满足当前搜索条件的总数）。
  - 验收：数据库 12 条时显示「12 人」。
- REQ-002.02 搜索框（占位文案「搜索用户名 / 昵称 / 备注」），输入防抖 300ms 后调用接口过滤；可一键清空。
  - 验收：输入关键字后列表只显示匹配项，清空后恢复。
- REQ-002.03 排序 Chip 单选：最新添加（默认）、粉丝最多、仓库最多；切换后从第一页重新加载。
  - 验收：切换「粉丝最多」后按粉丝数倒序。
- REQ-002.04 卡片内容：圆形头像 48px；昵称加粗（为空显示 login）；`@login` 次要色；右上角 ↗ 图标；bio 最多 2 行；公司 / 所在地一行（各自为空时隐藏，都为空时整行隐藏）；粉丝 / 仓库 / 关注统计（数值缩写 1.2k、3.4M，等宽数字）；标签 Chip（无则隐藏）；备注最多 1 行（无则隐藏）。
  - 验收：空字段对应行不渲染；数值缩写正确。
- REQ-002.05 点击卡片用系统浏览器打开该用户 `htmlUrl`；卡片可点击区域 ≥44×44，并有无障碍标签「打开 {login} 的 GitHub 主页」。
  - 验收：点击卡片调用浏览器打开对应主页。
- REQ-002.06 下拉刷新重新加载第一页；滚动到底部自动加载下一页（每页 20 条），加载中底部显示加载指示，无更多数据时不再请求。
  - 验收：25 条数据时首屏 20 条，滚动到底后共 25 条且不再请求。
- REQ-002.07 状态：首次加载显示骨架卡片；无数据显示插画 + 「系统中还没有 GitHub 人员，请在 Web 端添加」；搜索无结果显示「没有匹配的人员」；网络错误显示「加载失败」+「重试」按钮，点击重试重新请求。
  - 验收：断开后端时显示加载失败，恢复后点击重试显示列表。

### REQ-003 设置页

- REQ-003.01 主题切换：浅色 / 深色二选一，切换立即生效；默认浅色，不跟随系统外观变化（2026-11-08 需求变更：去掉「跟随系统」）。
  - 验收：选择深色后界面切换为深色主题；系统切换深色 / 浅色时 App 主题不变。
- REQ-003.02 后端连接状态：调用 `healthCheck`，显示「已连接」/「未连接」/「检查中…」。
  - 验收：后端停止时显示「未连接」。
- REQ-003.03 显示 App 版本号（取自应用配置）。
  - 验收：显示 `1.0.0`。

### REQ-004 视觉与体验

- REQ-004.01 使用 HeroUI Native + Uniwind 与工程主题色，浅色 / 深色模式下文本与背景对比度满足 WCAG AA；所有文案中文；列表滚动流畅（`FlatList` 虚拟化、头像缓存）。
  - 验收：两种模式下截图检查无不可读文本。
