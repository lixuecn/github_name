# 需求：GitHub 人员信息管理

## 1. 概述

系统用于收集和展示 GitHub 用户的公开资料，分两端：

| 端 | 定位 | 能力 |
| --- | --- | --- |
| Web（`apps/web`） | 管理端 | 按用户名搜索 GitHub 用户，加入系统，并对已加入的人员进行增删改查 |
| Android App（`apps/native`） | 展示端 | 只读浏览系统中已加入的人员 |

- 系统**不包含登录注册**，所有页面与接口直接访问
- 人员数据全局共享，存储于 PostgreSQL（Prisma）
- GitHub 资料由服务端调用 GitHub REST API 获取，客户端不直接请求 GitHub

### 不在本期范围

- 用户注册、登录、权限控制
- GitHub 仓库、提交、贡献图等资料以外的数据；GitHub OAuth / 私有信息
- 定时自动同步（只支持手动刷新）
- App 端的新增、编辑、删除；App 人员详情页
- iOS 专门适配与验收（代码可共用，本期只验收 Android）

## 2. Web 端（管理端）

页头导航新增入口「GitHub 人员」，对应页面 `/github`。页面分上下两区：上方搜索，下方人员列表。

### 2.1 搜索

- 输入 GitHub 用户名，回车或点击「搜索」发起查询
- 校验：去除首尾空格，为空不请求；1–39 个字符，仅字母、数字、连字符，不能以连字符开头或结尾，否则提示「GitHub 用户名格式不正确」
- 结果卡片展示：头像、昵称、用户名、简介、公司、所在地、博客、Twitter、公开仓库数、粉丝数、关注数、GitHub 注册时间、主页链接（新窗口打开）
- 若该用户已在系统中，卡片显示「已添加」标记，不再显示「加入系统」按钮
- 状态与提示：

| 场景 | 表现 |
| --- | --- |
| 查询中 | 加载骨架，搜索按钮禁用 |
| 用户不存在 | 「未找到该 GitHub 用户」 |
| GitHub 限流 | 「GitHub 请求过于频繁，请稍后再试」 |
| 其他错误 | 「查询失败，请稍后重试」 |

### 2.2 加入系统（增）

- 搜索结果卡片上点击「加入系统」，可选填备注（≤200 字）
- 以 GitHub 用户 ID（非 login）去重，重复添加提示「该用户已在系统中」
- 成功提示「添加成功」，下方列表立即刷新

### 2.3 人员列表（查）

- 每项展示：头像、昵称、用户名、备注、标签、粉丝数、公开仓库数、最后同步时间
- 关键字过滤（用户名 / 昵称 / 备注）
- 排序：添加时间（默认倒序）、粉丝数、仓库数
- 分页：每页 20 条
- 空状态：「还没有添加任何 GitHub 用户，先在上方搜索一个吧」
- 桌面端用表格，窄屏用卡片

### 2.4 编辑与同步（改）

- **编辑**：弹窗修改备注（≤200 字）与标签（≤5 个，每个 ≤20 字），成功提示「保存成功」
- **从 GitHub 刷新**：按 GitHub 用户 ID 重新拉取资料，覆盖 GitHub 字段并更新最后同步时间，不覆盖备注 / 标签
  - 对方改了 login：以新 login 展示
  - 对方账号已不存在：提示「该 GitHub 用户已不存在」，记录保留

### 2.5 删除（删）

- 点击「删除」弹出确认框「确定将 {login} 从系统中移除吗？」，确认后删除并提示「已删除」
- 只删除本系统数据，不影响 GitHub

## 3. Android App（展示端）

只读，打开即进入人员列表，**没有详情页**：卡片直接展示主要信息，点击卡片用系统浏览器打开该用户的 GitHub 主页。

### 3.1 信息架构

```
底部 Tabs
├── 人员（默认）  → 人员列表；点击卡片 → 系统浏览器打开 GitHub 主页
└── 设置          → 主题切换（浅色 / 深色，默认浅色，不跟随系统）、后端连接状态、版本号
```

### 3.2 人员列表

```
┌──────────────────────────────┐
│ GitHub 人员            12 人 │  ← 大标题 + 总数
│ ┌──────────────────────────┐ │
│ │ 🔍 搜索用户名 / 昵称 / 备注 │ │  ← 输入防抖 300ms，调接口过滤
│ └──────────────────────────┘ │
│ [最新添加] [粉丝最多] [仓库最多] │  ← 排序 Chip，单选
│ ┌──────────────────────────┐ │
│ │ (头像) Linus Torvalds   ↗ │ │  ← ↗ 提示可跳转 GitHub
│ │        @torvalds          │ │
│ │ Linux 内核作者…（最多 2 行） │ │
│ │ 🏢 Linux Foundation · 📍 Portland │  ← 公司 / 所在地，为空不显示
│ │ 👥 230k  📦 8  👤 0        │ │  ← 粉丝 / 仓库 / 关注
│ │ [前端] [后端]              │ │  ← 标签，无则不显示
│ │ 备注：……（最多 1 行）        │ │  ← 无备注不显示
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ …                        │ │
└──────────────────────────────┘
```

- 卡片：圆形头像 48px；昵称加粗（为空显示 login）；`@login` 次要色；空字段整行隐藏
- 交互：点击卡片打开 `htmlUrl`；下拉刷新；上拉加载更多（每页 20 条）
- 实现：`FlatList` / `FlashList` 渲染；头像用 `expo-image`，带缓存与占位
- 状态：

| 场景 | 表现 |
| --- | --- |
| 首次加载 | 骨架卡片 |
| 无数据 | 插画 + 「系统中还没有 GitHub 人员，请在 Web 端添加」 |
| 搜索无结果 | 「没有匹配的人员」 |
| 网络错误 | 「加载失败」+「重试」按钮 |

### 3.3 视觉规范

- HeroUI Native + Uniwind，沿用工程主题色，支持浅色 / 深色（`app-theme-context`）
- 数字用等宽字体并缩写（1.2k、3.4M）；时间用相对时间（「2 天前」）
- 可点击区域 ≥ 44×44，文本对比度满足 WCAG AA
- 所有文案中文
- 移除 Expo 脚手架自带的 Drawer、示例 Tabs、Modal 页面

## 4. 技术方案

### 4.1 数据模型

在 `packages/db/prisma/schema/schema.prisma` 新增 `GithubProfile`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String (cuid) | 主键 |
| `githubId` | Int, unique | GitHub 用户 ID，去重依据 |
| `login` | String, index | GitHub 用户名 |
| `name` / `bio` / `company` / `location` / `blog` / `twitterUsername` | String? | 公开资料 |
| `avatarUrl` / `htmlUrl` | String | 头像、主页 |
| `publicRepos` / `followers` / `following` | Int | 统计 |
| `githubCreatedAt` | DateTime | GitHub 注册时间 |
| `note` | String? | 备注 |
| `tags` | String[] | 标签 |
| `syncedAt` | DateTime | 最后同步时间 |
| `createdAt` / `updatedAt` | DateTime | 时间戳 |

修改后运行 `pnpm db:generate` 与 `pnpm db:migrate`。

### 4.2 接口（tRPC）

在 `packages/api/src/routers/github.ts` 新增路由并合并进 `appRouter`，均为 `publicProcedure`，入参用 Zod 校验：

| 过程 | 类型 | 使用方 | 说明 |
| --- | --- | --- | --- |
| `github.search({ username })` | query | Web | 调 GitHub `GET /users/{username}`，返回资料 + `existsInSystem` |
| `github.list({ keyword?, sort, cursor? })` | query | Web / App | 分页查询，返回 `items`、`total`、`nextCursor` |
| `github.create({ username, note? })` | mutation | Web | 服务端重新拉取资料后入库，不信任前端传入的资料 |
| `github.update({ id, note?, tags? })` | mutation | Web | 编辑备注 / 标签 |
| `github.sync({ id })` | mutation | Web | 调 GitHub `GET /user/{githubId}` 重新同步 |
| `github.delete({ id })` | mutation | Web | 删除 |

- GitHub 错误映射：404 → `NOT_FOUND`，403/429 → `TOO_MANY_REQUESTS`；请求超时 10s
- 可选环境变量 `GITHUB_TOKEN`（`apps/server/.env.schema` 声明，敏感）：配置后限额从 60 次/小时提升到 5000 次/小时；Lambda 环境同步加入 `env.lambda.ts`
- GitHub 客户端在 `apps/server/src/services.ts` 创建并注入 tRPC context
- 搜索结果内存缓存 60s

### 4.3 移动端

- Expo Router：根布局改为 `(tabs)`，包含 `index`（人员）与 `settings`（设置）
- 通过 `utils/trpc.ts` 调用 `github.list`，用 `useInfiniteQuery` 分页
- 外链用 `expo-web-browser` 或 `Linking.openURL` 打开
- 开发用 `pnpm dev:native`（Expo Go / Dev Client），发布用 EAS Build 生成 APK

## 5. 非功能需求

- **安全**：`GITHUB_TOKEN` 只在服务端，不下发、不写日志；外链加 `rel="noopener noreferrer"`；`blog` 校验为 http(s) 后才渲染为链接；搜索与写接口按 IP 限流（每分钟 30 次）
- **性能**：列表接口 P95 < 300ms（不含 GitHub 调用）；App 列表滚动 60fps
- **体验**：提示均为中文；搜索框支持回车、有 label；删除需二次确认
- **兼容**：Web 支持主流桌面与移动浏览器；App 支持 Android 10+

## 6. 验收标准

### Web

- [ ] 无需登录即可访问 `/github`
- [ ] 搜索存在的用户（如 `torvalds`）显示完整资料；不存在时提示「未找到该 GitHub 用户」
- [ ] 非法用户名提示格式错误且不发请求
- [ ] 「加入系统」后数据库新增记录、列表立即出现；重复添加提示「该用户已在系统中」
- [ ] 已加入的用户再次搜索显示「已添加」
- [ ] 编辑备注 / 标签后刷新页面仍保留
- [ ] 「从 GitHub 刷新」后同步时间更新，备注 / 标签不变
- [ ] 删除需二次确认，确认后从数据库和列表中消失
- [ ] 列表支持关键字过滤、排序、分页

### Android App

- [ ] 打开 App 默认进入「人员」列表，展示 Web 端已加入的全部人员
- [ ] 卡片展示主要资料，空字段不显示；点击卡片在浏览器打开 GitHub 主页
- [ ] 支持搜索、排序切换、下拉刷新、上拉加载更多
- [ ] 加载中、无数据、搜索无结果、加载失败均有对应界面，失败可重试
- [ ] 浅色 / 深色模式显示正常
- [ ] Web 端增删人员后，App 下拉刷新可看到变化

### 工程

- [ ] 超出频率限制返回 `TOO_MANY_REQUESTS`
- [ ] 未配置 `GITHUB_TOKEN` 时功能可用（受匿名限额约束）
- [ ] `pnpm check-types` 与 `pnpm check` 通过
