# 需求：基础登录注册功能

## 背景

用户需要通过用户名和密码注册账号、登录系统，登录后才能访问受保护的页面与接口。功能需同时覆盖 Web 端（`apps/web`）与移动端（`apps/native`），认证基于 Better Auth（启用 `username` 插件），数据存储于 PostgreSQL。

## 目标

- 新用户可以用用户名 + 密码注册账号
- 已注册用户可以用用户名 + 密码登录
- 登录用户可以退出登录
- 未登录用户无法访问受保护页面与接口

## 不在本期范围

- 邮箱注册 / 登录、邮箱验证
- 第三方登录（Google、GitHub 等）
- 找回 / 重置密码
- 手机号 / 验证码登录
- 双因素认证

## 功能需求

### 1. 注册

- 表单字段：
  - 用户名：必填，3–20 个字符，仅允许字母、数字、下划线，不区分大小写
  - 密码：必填，至少 8 个字符
  - 确认密码：必填，需与密码一致
- 前端在提交时校验，不通过时在对应字段下方显示错误提示
- 用户名已被占用时，提示「该用户名已被注册」
- 注册成功后自动登录，跳转到 `/dashboard`（移动端跳转到首页），并提示「注册成功」
- 提交过程中按钮显示加载状态并禁用，防止重复提交

### 2. 登录

- 表单字段：用户名、密码（校验规则同注册）
- 用户名或密码错误时，统一提示「用户名或密码错误」，不区分具体是哪一项错误
- 登录成功后跳转到 `/dashboard`（移动端跳转到首页），并提示「登录成功」
- 提交过程中按钮显示加载状态并禁用
- 登录页与注册页之间可以互相切换

### 3. 退出登录

- 已登录用户在页头用户菜单（移动端在首页）中可以退出登录
- 退出后清除会话，跳转回首页

### 4. 访问控制

- Web：访问 `/dashboard` 时若未登录，重定向到 `/login`
- Web：已登录用户访问 `/login` 时，直接跳转到 `/dashboard`
- 移动端：未登录时首页显示登录 / 注册表单，登录后显示用户信息
- 后端：需要登录的 tRPC 接口使用 `protectedProcedure`，未登录调用返回 `UNAUTHORIZED`

### 5. 登录状态展示

- Web 页头：未登录时显示「登录」按钮；已登录时显示用户名，点击展开菜单（含退出登录）
- `/dashboard` 页面显示「欢迎，{用户名}」，并调用 `privateData` 接口展示受保护数据
- 界面中不出现任何邮箱相关的字段或文案

## 技术说明

- 服务端在 `packages/auth` 中启用 Better Auth `username` 插件，客户端（Web 与 Native）同步启用 `usernameClient`，修改后运行 `pnpm auth:generate` 并迁移数据库
- Better Auth 的 `user` 表要求 `email` 字段，注册时由系统根据用户名生成内部占位邮箱（不对用户展示、不用于登录），开发时以 Better Auth 文档为准确认最佳做法
- 关闭邮箱密码的公开登录入口，用户只能通过用户名登录

## 非功能需求

- 安全：
  - 密码由 Better Auth 哈希存储，不以明文存储或记录到日志
  - Web 端会话使用 httpOnly cookie；移动端会话存储在 `expo-secure-store`
  - 登录、注册接口需开启频率限制，防止暴力破解
- 体验：所有提示文案使用中文；表单支持键盘提交（回车）；输入框有对应的 label
- 兼容：Web 端支持主流桌面与移动浏览器；移动端支持 iOS 与 Android

## 验收标准

- [ ] 使用新用户名注册成功，数据库 `user` 表中新增一条记录，并自动进入登录状态
- [ ] 使用已注册的用户名（含大小写不同）再次注册，提示「该用户名已被注册」
- [ ] 用户名格式不合法、密码少于 8 位、两次密码不一致时，表单显示对应错误且不发起请求
- [ ] 使用正确的用户名和密码登录成功并跳转；使用错误的密码登录时提示「用户名或密码错误」
- [ ] 注册与登录界面均不出现邮箱输入框
- [ ] 刷新页面或重启 App 后仍保持登录状态
- [ ] 退出登录后，访问 `/dashboard` 被重定向到 `/login`
- [ ] 未登录时直接调用 `privateData` 接口返回 `UNAUTHORIZED`
- [ ] Web 端与移动端均能完成注册、登录、退出流程
- [ ] `pnpm check-types` 与 `pnpm check` 通过
